⸻

1. 전체 방향

인터페이스 테이블

역할:
	•	배치 대상 판별
	•	중복 배치 실행 방지

사용 컬럼:
	•	ACCOUNT
	•	ACCOUNT_STATUS
	•	BATCH_RUN

기준:
	•	ACCOUNT_STATUS = 3
	•	BATCH_RUN = 'N'

이면 배치 처리 대상

⸻

배치 히스토리 테이블

역할:
	•	배치 실행 로그만 남김
	•	시작 시간 / 종료 시간 / 성공 여부 / 알림 여부 정도만 관리

즉 히스토리는 판별용 아님
그냥 이력용

⸻

2. BATCH_RUN 처리 방식

배치 대상 조회

SELECT ACCOUNT
FROM system_account_interface
WHERE ACCOUNT_STATUS = '3'
  AND BATCH_RUN = 'N'

배치 처리 완료 후

해당 시스템 계정의 BATCH_RUN = 'Y' 로 변경

UPDATE system_account_interface
SET BATCH_RUN = 'Y'
WHERE ACCOUNT = ?
  AND ACCOUNT_STATUS = '3'
  AND BATCH_RUN = 'N'


⸻

3. 다시 승인받는 경우

네 방식대로 하면 됨.

흐름
	1.	시스템 계정이 만료됨
	•	ACCOUNT_STATUS = 3
	•	BATCH_RUN = N
	•	배치 처리 후 BATCH_RUN = Y
	2.	나중에 다시 승인 프로세스 탐
	•	구독 신청
	•	구독 승인
	3.	다시 승인 가능한 상태가 되면
	•	BATCH_RUN = N 으로 초기화
	4.	이후 또 만료되면
	•	다시 배치 대상이 됨

⸻

4. 구독 신청 시 / 구독 승인 시 언제 N으로 바꿀까?

추천

구독 승인 시 반드시 BATCH_RUN = N으로 변경

그리고
구독 신청 시에도 넣어도 되지만, 필수는 승인 시점이라고 보면 돼.

정리
	•	구독 신청 시: 넣어도 됨
	•	구독 승인 시: 꼭 넣는 걸 추천

이유:
	•	승인 시점이 실제로 다시 정상 상태에 들어가는 시점이라 더 명확함
	•	신청 시 누락되더라도 승인 시 한 번 더 보정 가능

즉 실무적으로는:

가장 안전한 방식
	•	신청 시 N
	•	승인 시도 N

둘 다 넣기

5. 배치 히스토리 테이블은 어떻게 둘까

네 말대로 단순하게 가면 돼.

추천 최소 컬럼

CREATE TABLE batch_expire_hist (
    hist_id         BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    batch_type      VARCHAR(50) NOT NULL,
    start_at        DATETIME NOT NULL,
    end_at          DATETIME NULL,
    process_status  VARCHAR(20) NOT NULL,
    notify_yn       CHAR(1) NOT NULL DEFAULT 'N',
    target_count    INT NOT NULL DEFAULT 0,
    success_count   INT NOT NULL DEFAULT 0,
    fail_count      INT NOT NULL DEFAULT 0,
    error_message   VARCHAR(2000) NULL,
    created_at      DATETIME NOT NULL,
    updated_at      DATETIME NOT NULL
);


⸻

6. 컬럼 의미

batch_type
	•	어떤 배치인지 구분
	•	예: EXPIRE_SYSTEM_ACCOUNT

start_at
	•	배치 시작 시간

end_at
	•	배치 종료 시간

process_status
	•	PROCESSING
	•	SUCCESS
	•	FAIL
	•	필요하면 PARTIAL_SUCCESS

notify_yn
	•	이번 배치에서 알림 전송했는지 여부

target_count
	•	배치 대상 시스템 계정 수

success_count
	•	배치 처리 성공한 시스템 계정 수

fail_count
	•	배치 처리 실패한 시스템 계정 수

error_message
	•	배치 전체 실패나 대표 에러 메시지

⸻

7. 배치 처리 순서

1) 배치 시작 시 히스토리 insert

INSERT INTO batch_expire_hist (
    batch_type,
    start_at,
    process_status,
    notify_yn,
    target_count,
    success_count,
    fail_count,
    created_at,
    updated_at
) VALUES (
    'EXPIRE_SYSTEM_ACCOUNT',
    NOW(),
    'PROCESSING',
    'N',
    0,
    0,
    0,
    NOW(),
    NOW()
);


⸻

2) 만료 대상 조회

SELECT ACCOUNT
FROM system_account_interface
WHERE ACCOUNT_STATUS = '3'
  AND BATCH_RUN = 'N'


⸻

3) 계정별 처리

각 시스템 계정에 대해
	•	구독중인 건 → 구독 해제
	•	구독 신청 중인 건 → 신청 반려
	•	프로젝트 관리자 조회
	•	알림 전송
	•	성공 시 BATCH_RUN = 'Y'

⸻

4) 배치 종료 시 히스토리 update

UPDATE batch_expire_hist
SET end_at = NOW(),
    process_status = ?,
    notify_yn = ?,
    target_count = ?,
    success_count = ?,
    fail_count = ?,
    error_message = ?,
    updated_at = NOW()
WHERE hist_id = ?


⸻

8. process_status 기준 추천

SUCCESS
	•	대상 전체 정상 처리 완료

PARTIAL_SUCCESS
	•	일부 계정 성공, 일부 실패
	•	이 값이 필요 없으면 빼도 됨

FAIL
	•	전체 실패하거나 핵심 로직 실패

개인적으로는 PARTIAL_SUCCESS 넣는 걸 추천하지만,
단순하게 가려면 PROCESSING / SUCCESS / FAIL 3개만 써도 됨.

9. 최종 추천안

인터페이스 테이블

추가 컬럼:
	•	BATCH_RUN CHAR(1) DEFAULT 'N'

배치 대상 조건:

ACCOUNT_STATUS = '3'
AND BATCH_RUN = 'N'

배치 완료 후:

BATCH_RUN = 'Y'

재승인 시:

BATCH_RUN = 'N'


⸻

히스토리 테이블

남기는 것:
	•	배치 시작 시간
	•	배치 종료 시간
	•	처리 상태
	•	알림 전송 여부
	•	대상 건수
	•	성공 건수
	•	실패 건수
	•	에러 메시지
